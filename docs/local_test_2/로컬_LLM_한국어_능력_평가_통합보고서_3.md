# 로컬 LLM 한국어 질의응답 능력 평가 — 통합 보고서

1차 테스트(초기 실행)와 2차 테스트(test3.zip, 재실행) 결과를 통합 비교하고, 연구 목적·모델 선정 근거·연구 설계를 함께 정리한 보고서입니다.

---

## 요약 (TL;DR)

- **1차 테스트에서 카나나(Kanana 1.5 8B)의 응답 끝에 특수 토큰(eot_id 등)이 10문항 전부 남아있는 오류가 발견됨** → format 점수가 0/10으로 처리되어 총점이 18.0/30에 그침.
- **2차 테스트에서 해당 오류가 해결됨** → 특수 토큰 노출 0건, format 점수 9/10으로 상승, 총점 **18.0 → 27.0 (+50%)**.
- 세 모델의 **답변 내용(content) 자체는 1차·2차에서 동일**했습니다. 즉 이번 개선은 모델의 한국어 이해력이 좋아진 것이 아니라, 응답 후처리(토큰 정리) 문제가 고쳐진 것입니다.
- 성능 지표(속도·VRAM)는 1차·2차 모두 오차 범위 내에서 비슷했고, 순위도 그대로였습니다.
- 최종적으로 **카나나는 안정성(재현성·낮은 오류율·최고 총점)**, **엑사원은 완곡한 표현 이해도(Q09 등)**에서 강점을 보여줬습니다.
- 이 중 **최종 로컬 모델로는 Kanana를 선정**했습니다.

---

## 1. 목적

한국어가 공통어로 통용되는 공공기관·기업 환경에서 사용할 상용 모델과 견주어, 오픈(로컬) 모델의 한국어 능력(이해력·일관성)을 비교합니다. 이를 통해 연구 또는 서비스 구현에 적합한 오픈 모델을 탐색·선정하는 것이 이번 평가의 목적입니다.

- 1단계: 선정된 로컬 모델(Kanana, EXAONE, Llama) 간 테스트 비교 → 대표 로컬 모델 선정
- 2단계(예정): 대표 로컬 모델과 빅테크 상용 모델, 독파모(모티프) 상용 모델 3개를 동시 비교 분석
- 확장 계획(예정): 로컬 모델을 양자화·멀티 에이전트(연합) 구성으로 만들어 상용 모델과 재비교

이번 통합 보고서는 위 1단계의 1차·2차 테스트 결과를 정리한 것이며, 2단계와 확장 계획은 [§6 향후 계획](#6-향후-계획)에 별도로 정리했습니다.

## 2. 모델 선정 이유

### 2.1 Kanana 1.5 8B Instruct (kanana-1.5-8b-instruct-2505)

- 국산 8B 이하 체급 1위
- 압도적인 토크나이저 효율 — 비용 40% 절감, 속도 60% 개선
  1. 주요 모델들과의 크기 비교 (12만 대의 의미)
  2. '크기'보다 중요한 '한국어 배치 압축률'
- 필터링 성능의 안정성, 낮은 악용 가능성 — 보안성 측면에서도 우수

### 2.2 EXAONE-3.5-7.8B-Instruct (GGUF)

- **LogicKor** (국내 LLM 평가 표준): 한국어 추론·수학·글쓰기·코딩 등 6개 분야를 다각도로 평가하는 국내 대표 지표. EXAONE 상위 체급은 LogicKor에서 9점대(10점 만점)를 기록하며 한국어 표현 및 논리 이해에서 최상위권 성능을 입증
- K-엑사원(같은 계열)이 EXAONE을 선정하게 된 계기
  1. 전문가 평가 지표(35점 배점) — 전체 참여팀 중 최고점(29.5점) 획득
  2. 벤치마크 지표(40점 배점) — 글로벌 기준 최상위권 '환각 억제력'

### 2.3 Llama 3.1 8B Instruct (FP16) — 대조군

- Kanana 1.5 8B·EXAONE 7.8B를 비교할 기준이 되는 글로벌 범용 오픈모델로 선정. 국내 모델끼리만 비교하면 그 결과가 글로벌 모델 대비 어느 수준인지 확인하기 어렵기 때문
- 세 모델의 파라미터 규모가 비슷(Kanana 1.5 ≈8B, EXAONE 3.5 ≈7.8B, Llama 3.1 ≈8B)해, 크기 차이의 영향을 최소화한 상태에서 한국어 질의 처리 결과를 비교 가능
- 모델 최대 context length는 131,072이지만, 다른 모델과 조건을 맞추기 위해 실험에서는 사용 context length를 8,192로 통일
- 목적은 단순히 세 번째 모델을 추가하는 것이 아니라, 국내 모델과 글로벌 범용 모델이 동일한 파라미터 규모에서 한국어 질문을 어떻게 처리하는지 비교하는 기준점 확보 — 국내 모델의 실제 강점과, 글로벌 모델과 큰 차이가 없는 영역을 함께 확인하기 위함

## 3. 연구 설계

1. **평가지표 설계** — 예상 평가 점수 및 채점 방식을 정의. 평가지표·교안 내용을 토대로 평가 영역을 선정(5개 영역).
2. **로컬 모델 선정** — 위 §2의 선정 이유와 근거에 따라 Kanana, EXAONE, Llama 3종을 테스트 대상으로 확정.
3. **로컬 모델 안전성 검사** — 테스트 이전 단계에서 각 모델의 안전성을 사전 점검.
4. **로컬 모델 테스트**
   - 1차 실험: 오류 발생 (Kanana 응답에 특수 토큰이 그대로 노출되어 형식 채점에서 전 문항 감점)
   - 2차 실험: 통과 — 다만 한국어를 끝까지 정확히 읽어야 답할 수 있는 완독형 표현 이해 문항(예: 완곡한 거절, 중의어 해석)에서 모델 간 난이도 차이가 뚜렷하게 발생
5. **로컬 모델 선정(결과)** — 전체적으로 **카나나가 안정성**(재현성, 낮은 오류율, 최고 총점)에서 앞서 **최종 로컬 모델로 카나나를 선정**. 엑사원은 **완곡한 표현 이해**(간접 화행, 화용적 의도 파악)에서 다른 로컬 모델 대비 높은 이해도를 보였으나, 최종 선정에는 포함하지 않음.

아래 §4는 위 4번 단계(1차·2차 실험)의 실제 수치를 통합 비교한 내용입니다.

## 4. 1차 vs 2차 테스트 통합 비교

### 4.1 테스트 조건 (1차·2차 공통)

| 항목 | 값 |
|---|---|
| 테스트 문항 수 | 10 |
| 모델별 반복 횟수 | 2 (Run 1, Run 2) |
| Temperature | 0.0 |
| Context Length (적용값) | 8,192 |
| 대상 모델 | Llama 3.1 8B(F16) · Kanana 1.5 8B(F16) · EXAONE 7.8B(BF16) |

### 4.2 성능 지표 비교 (1차 → 2차)

| 모델 | 지표 | 1차 | 2차 | 변화 |
|---|---|---|---|---|
| Llama 3.1 8B | Cold Load (s) | 13.014 | 14.312 | +1.298 (+10.0%) |
| | Avg Total (s) | 6.382 | 7.591 | +1.209 (+18.9%) |
| | Gen Speed (tok/s) | 7.14 | 7.44 | +0.30 (+4.2%) |
| | Prompt Speed (tok/s) | 179.24 | 184.46 | +5.22 (+2.9%) |
| | VRAM (GB) | 5.55 | 5.82 | +0.27 (+4.9%) |
| Kanana 1.5 8B | Cold Load (s) | 11.878 | 12.576 | +0.698 (+5.9%) |
| | Avg Total (s) | 20.534 | 19.646 | −0.888 (−4.3%) |
| | Gen Speed (tok/s) | 6.54 | 6.85 | +0.31 (+4.7%) |
| | Prompt Speed (tok/s) | 190.59 | 194.47 | +3.88 (+2.0%) |
| | VRAM (GB) | 5.56 | 5.56 | 변화 없음 |
| EXAONE 7.8B | Cold Load (s) | 10.713 | 11.315 | +0.602 (+5.6%) |
| | Avg Total (s) | 13.203 | 13.043 | −0.160 (−1.2%) |
| | Gen Speed (tok/s) | 7.04 | 7.10 | +0.06 (+0.9%) |
| | Prompt Speed (tok/s) | 167.77 | 172.22 | +4.45 (+2.7%) |
| | VRAM (GB) | 5.79 | 5.79 | 변화 없음 |

**해석:** 세 모델 모두 1차·2차 간 성능 지표 변화가 ±20% 이내이며, 모델 간 상대적 순위(EXAONE이 가장 빠른 Cold Load, Llama가 가장 빠른 Gen Speed, Kanana가 가장 빠른 Prompt Speed지만 가장 긴 Avg Total)도 그대로 유지되었습니다. 즉 실행 간 자연스러운 변동 범위 안에 있으며, 모델 간 우열 관계에 실질적인 변화는 없었습니다.

### 4.3 품질 지표 비교 (1차 → 2차)

| 모델 | 1차 총점 | 2차 총점 | 변화 | 1차 Content | 2차 Content | 1차 Format | 2차 Format |
|---|---|---|---|---|---|---|---|
| Llama 3.1 8B | 13.0 / 30 | 13.0 / 30 | 변화 없음 | 10.0/20 | 10.0/20 | 3.0/10 | 3.0/10 |
| **Kanana 1.5 8B** | 18.0 / 30 | **27.0 / 30** | **+9.0 (+50.0%)** | 18.0/20 | 18.0/20 (변화 없음) | **0.0/10** | **9.0/10** |
| EXAONE 7.8B | 23.0 / 30 | 23.0 / 30 | 변화 없음 | 17.0/20 | 17.0/20 | 6.0/10 | 6.0/10 |

**해석:** Llama와 EXAONE은 1차·2차 점수가 완전히 동일했습니다. 변화는 오직 Kanana에서만 발생했으며, 그마저도 **content 점수는 18.0/20으로 그대로**이고 **format 점수만 0.0 → 9.0으로 개선**되었습니다. 즉 모델이 "더 똑똑해진" 것이 아니라, 답변 자체의 실질 내용은 1차와 2차가 동일했고 응답 형식(후처리) 문제만 해소된 것입니다.

### 4.4 핵심 발견: 카나나 특수 토큰 이슈

| 항목 | 1차 | 2차 |
|---|---|---|
| 특수 토큰 노출 문항 수 (Kanana) | 10 / 10 | 0 / 10 |
| Kanana format 점수 | 0.0 / 10 | 9.0 / 10 |
| Q01 JSON 그대로 파싱 가능 여부 (Kanana) | 실패 (토큰 잔존) | 성공 |
| Kanana 평균 답변 길이 | 230.2자 | 220.2자 (−4.3%) |

1차 테스트에서는 Kanana의 모든 응답 끝에 `eot_id` 등 템플릿 토큰이 그대로 남아 있었습니다. 이 때문에 Q01처럼 JSON 형식을 요구한 문항조차 후처리 없이는 파싱이 불가능했고, 10문항 모두 형식 기준을 위반해 format 점수가 0점 처리되었습니다. 2차 테스트에서는 이 토큰이 전혀 남지 않았고(0/10), 그 결과 format 점수가 9/10으로 상승했습니다. 남은 1문항(Q08)의 형식 미충족은 토큰 문제가 아니라 "자연스러운 짧은 확인 질문" 기준에 비해 답변이 지나치게 길고 장황했기 때문입니다.

이 변화 덕분에 Kanana는 2차 테스트에서 **총점 27.0/30으로 세 모델 중 1위**를 기록했습니다(1차에서는 EXAONE이 23.0으로 1위, Kanana는 18.0으로 최하위였음).

## 5. 결론: 대표 로컬 모델 선정

| 모델 | 강점 | 근거 | 최종 선정 |
|---|---|---|---|
| **Kanana 1.5 8B** | 안정성 | 재현성 가장 우수(변동률 최소), 2차 테스트 기준 총점 1위(27.0/30), 특수 토큰 문제 해결 후 형식 오류 최소(1/10) | **선정** |
| EXAONE 7.8B | 완곡한 표현 이해도 | Q09(완곡한 거절 신호 해석)에서 세 모델 중 유일하게 만점(3.0/3.0); Q10(위약금 산정 기준처럼 정보 부족 상황에서 단정하지 않고 안내)에서도 만점 | 미선정 (참고) |
| Llama 3.1 8B | — (대조군) | 한국어 공식 미지원 대조군으로서 예상대로 세 모델 중 최저 점수(13.0/30) — 한국어 특화 모델과의 격차를 정량적으로 확인하는 역할 | — (대조군) |

전체적으로 **카나나는 안정성**, **엑사원은 완곡한 표현에서 로컬 모델 대비 높은 이해도**를 보였습니다. 재현성·낮은 오류율·최고 총점을 종합적으로 고려해 **최종 로컬 모델은 Kanana로 선정**합니다. 엑사원의 완곡한 표현 이해도는 강점으로 기록해 두되, 이번 대표 모델 선정에는 반영하지 않았습니다.

## 6. 향후 계획

1. **3자 비교**: 위에서 선정한 대표 로컬 모델 Kanana와 빅테크 상용 모델, 독파모(모티프) 상용 모델을 동일한 평가지표·문항으로 동시 비교 분석.
2. **양자화 멀티 에이전트(연합) 비교**: 양자화 된 로컬 모델을 여러 모델을 연합(멀티 에이전트) 구조로 구성하고, 단일 상용 모델과의 테스트 결과를 비교.

두 계획 모두 아직 실행 전 단계이며, 실행 후 별도 보고서로 이어서 통합할 예정입니다.
